# CLAUDE.md

## Project

**Photo Town**: a McGill CodeJam 2026 hackathon demo. It's a small 3D town in the browser where NPCs wander, play idle and walk animations, and speak lines. The player takes or uploads a photo of a real person, and the app turns it into a stylized animated NPC named after that person.

**Scope is demo-only.** Aim for "works reliably on stage," not production. Prefer the simplest thing that looks good. Don't add backends, auth, databases, tests or build tooling beyond what's listed here unless asked.

## Stack

- Vite + vanilla JavaScript (ES modules), no framework
- Three.js for rendering. Import add-ons from `three/addons/...`; use `CSS2DRenderer` for name tags and speech bubbles.
- `@mediapipe/tasks-vision` FaceDetector, run in the browser
- Browser `speechSynthesis` for NPC voice lines
- No server. All generation happens client-side, and the build is static files.

## Commands

```sh
npm install        # postinstall copies MediaPipe WASM into public/mediapipe
npm run dev        # local dev at http://localhost:5173
npm run dev:lan    # HTTPS on the LAN (needed for the camera on phones)
npm run build      # static output in dist/
```

## Architecture

```
index.html, src/style.css   UI shell: header, "Add a resident" button, photo modal, NPC panel
src/main.js                 renderer, camera + OrbitControls, game loop, picking, wiring
src/world.js                town scenery, walkable radius, circular obstacles
src/npc.js                  NPC: wander state machine, animation mixer, name tag, speech bubble
src/speech.js               text-to-speech + line templates ({name}, {other})
src/storage.js              localStorage persistence of resident specs (wrapped in try/catch)
src/avatar/fromPhoto.js     photo → spec: face detection, aligned oval face crop, color sampling
src/avatar/cartoonFace.js   drawn faces for the built-in townsfolk
src/avatar/build.js         spec → Three.js avatar (node hierarchy + face decal)
src/avatar/animations.js    Idle / Walk / Wave / Talk AnimationClips
public/models/              blaze_face_short_range.tflite (committed)
public/mediapipe/           WASM runtime (generated by postinstall, gitignored)
```

### Key decisions (keep these unless told otherwise)

- **Template avatars, not free-form 3D reconstruction.** One procedural stylized body is customized from the photo: the face texture is projected onto the head, and skin, hair and shirt colors are sampled from the image. Hair style, pants, height and build are seeded from a hash of the name. This guarantees rigging and animation always work.
- **One shared node hierarchy** for every avatar: `Body`, `Neck`, `ArmL`, `ArmR`, `LegL`, `LegR`. Animations are node-rotation and position keyframe clips that target these names. Any new avatar part or generator must keep these names so the shared clips still apply.
- **Avatar is separate from the NPC group.** The NPC's outer group holds position, rotation, spawn scale, the name tag and the selection ring. The inner avatar root is what gets animated and what is exported to `.glb` (`GLTFExporter`, binary, with animations).
- **Serializable spec.** Residents are saved as plain JSON specs (name, face data URL, colors, seed values) and rebuilt on load. Built-in townsfolk are not saved.
- **Stylized look**, low-poly, `MeshStandardMaterial`. Keep each avatar well under ~5k triangles so it runs on phones.
- **Possible upgrade later:** a server-side photo-to-3D generator could replace `fromPhoto.js` + `build.js`. It must output a glTF skinned to the same hierarchy above.

## Conventions

- Plain JS, small modules, no TypeScript. Format with 2-space indentation and single quotes.
- Every browser API that can be missing or fail needs a graceful fallback: camera, `speechSynthesis`, MediaPipe, `localStorage`, canvas `filter`. The demo must never hard-crash. For example, if face detection fails, fall back to a center crop and tell the user.
- UI must work at phone width and with touch.
- Pin exact versions for any CDN URL.

## Privacy

The app handles photos of real people:
- Require the consent checkbox before generating.
- Never upload photos anywhere. Processing stays in the browser.
- Keep only the cropped face in the saved spec, never the original photo.
